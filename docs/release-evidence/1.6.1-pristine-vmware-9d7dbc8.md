# Pristine packaged installation and reboot on VMware

Test date: 2026-11-17, Europe/Moscow. The exact candidate
`9d7dbc8defd7d4e1fc6844e88c69031403ec778d` (tree
`18f28efb11ffd3da9421332a68cfdf84297d115b`) was installed on a fresh Ubuntu
24.04.5 LTS amd64 VM. Its disk came from the [previously authenticated Ubuntu
image](1.6.1-pristine-vmware-b5fa4a4.md). Cloud-init created a dedicated
operator on an isolated VMware NAT interface. SSH used a fresh client key and
the server key pinned from the local console. Before installation, cloud-init
was complete, product files were absent, and easy-waf, HAProxy, PostgreSQL,
CrowdSec and Fail2Ban had no installed packages.

## Backup timer and actual reboot

Before the first reboot, the initial timer check found `easy-waf-backup.timer`
enabled but inactive. The package's standalone first-install policy enables
the timer for the next boot. The full installer had omitted starting it after
provisioning. A full rerun with the installer from `11b81d2`, the same source
inputs and the same DEB started the enabled timer while the original boot ID
still held. The scheduler reported a next run. The focused installer test
covered operator opt-out, skipped service startup and failed timer start.

A subsequent real reboot changed the boot ID from
`b36ed0e6-1f7d-4a4a-88f7-2463fc75e4d7` to
`b29e41e2-33c3-44cd-ab23-599c425c4ef0`. The backup timer and the ten checked
services recovered. Before any new Apply, the publication answered HTTP 200
and saved and applied generations matched. The package, payload, schema,
management TLS, CrowdSec reads, API Apply and HAProxy checks passed again.
Smoke returned 19/0/2 and the Windows client verified the marker again.

The test VM was powered off. Private logs and credentials remain on its disk.
The PVE appliance and existing VMware restore clone were outside the test
scope. Manual browser Apply, WAN access and signed-release acceptance remain
separate checks for this candidate.
