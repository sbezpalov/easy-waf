# VMware upgrade to schema 028

The Ubuntu 24.04.5 amd64 acceptance clone upgraded from `6e1fb75` and schema
027 to the package built from `ecadad2` and schema 028. The source tree was
`4c6cdc87e509962dfda698322fa47021561700c5`. Compared with `e7b2fad`, which ran
through CI, this tree changes only `CHANGELOG.md`.

## Build and test evidence

- All three [GitHub CI jobs for e7b2fad](https://github.com/sbezpalov/easy-waf/actions/runs/44148367373)
  passed. Native Windows Go 1.27.4 tests for the UI and generator also passed.
- The independent Ubuntu CI run used Go 1.27.4, HAProxy 2.8.30 and PostgreSQL 16.
  Seven gates passed, including vet, lint, golden tests, live HAProxy, `make verify`
  and shell syntax. The full race gate failed with 855 top-level passes, two
  failures and no test skips. `TestExtractMMDB_capsDecompressedSize` and
  `TestAPTLogDownloadRejectsDecodedTotalBeforeWritingExcess` both reported
  accesses attributed to the same goroutine. The affected packages had no source
  changes since `6e1fb75`. Both tests passed twice each on `6e1fb75` and on
  `e7b2fad` in focused Linux race runs with the same toolchain. The original
  reports remain unresolved. The full local race gate remains open.
- Fresh Linux/amd64 govulncheck against `vuln.go.dev` exited zero and reported
  `No vulnerabilities found` for the package source tree.
- The release workflow's preflight and build commands produced unsigned amd64
  and arm64 DEBs and tarballs. Checksums, ELF architectures, DEB metadata,
  matching tar and DEB payloads, and amd64 CLI version output passed. The amd64
  DEB installed on the clone has SHA-256
  `034e69334bd54df55d3f8a43fd62c8c473c3c88fed50e26a6a33bff29f3cef66`.
  The arm64 package was inspected without executing it.

## Installed verification and recovery

APT reinstalled the verified package with `--force-confold` after taking a
matched backup. PostgreSQL recorded migration 028. Settings, full application
and certificate records, environment, management certificate and fixture bundle
matched the pre-upgrade baseline. All four installed binary hashes and three
running daemon executable hashes matched the package. Ten checked units were
active and enabled, and the failed-unit list was empty.

The served HTML matched the bundle hash and the CSP matched its single inline
script. The authenticated edge API reported equal saved and applied generations,
`pending=false` and the same revision for the live artifact and last apply.
HAProxy stats and the host broker's APT status RPC passed. The Windows client
verified SNI, test CA, certificate and exact HTTPS marker. Smoke passed 19 checks
with zero failures and two skips for the separate admin token and optional MMDB
upload. The GeoIP lookup passed in that run.

The prior exact DEB and root-private matched pre-upgrade backup remain available
for rollback through the packaged restore command. A new schema 028 checkpoint
is also retained on the clone. Fresh restore and reboot were outside this run.
PVE continues to use its separate package and state. Release signing and
approval remain open.

Local artifacts and original race reports are in
`.ai/artifacts/candidate-e7b2fad/`. Private backup and probe data remain on the
clone under `acceptance-work/candidate-e7b2fad`.
