# Reliable body-policy E2E — f6bc4ad

Test date: 2026-11-16, Europe/Moscow. Exact code commit:
`f6bc4adc9bc4e49b476dc64743a2df416cf9a4fd`, version 1.6.1. Changes affect the
nightly test launcher, its regression and verification wiring; no appliance Go
code, schema, dependency or installed package changed.

## Confirmed false-success defect

The body-policy E2E consumed `docker run` output through process substitution.
Its exit status was lost: a failed case container could yield no records, leave
the failure counter at zero and print `OK`. A partial stream of passing records
had the same problem. A Docker-free regression invoking the actual entrypoint
reproduced the original bug: a mocked runner exit 42 was falsely accepted.

The script now materializes output only from a successfully completed case
container and requires one record for every `check` call in the generated case
script. Missing or incomplete results fail the E2E. The regression covers runner
failure, partial output followed by failure, empty success, partial success,
complete HTTP failure and a complete passing suite. Docker and startup sleeps
are mocked only in this result-handling regression; real networking is separate.

All six cases passed on Windows and Linux. The regression is included in
`make verify` and ShellCheck, so it runs without Docker, root or networking in
ordinary CI. Full Linux `make verify` and syntax checks passed for the exact
staged tree committed above. ShellCheck 0.9.0 in Ubuntu and native Windows
ShellCheck 0.11.0 passed. No Go/race or vulnerability scan was rerun or claimed
for this script-only change; the preceding full candidate gates are recorded
[separately](1.6.1-local-gates-c27c77b.md).

## Confirmed Windows launcher defect

The first actual Windows Git Bash run failed before HTTP cases: MSYS rewrote
HAProxy's `/cfg/haproxy.cfg` argument into a path under the Windows Git installation.
The startup guard rejected the failure and the owned fixtures were cleaned.

The launcher now converts only the host temporary bind source with `cygpath -m`
when available, uses `--mount` and exports `MSYS_NO_PATHCONV=1` so container paths
remain Linux paths. This follows the other portable Docker launchers in the
repository; without cygpath it keeps the native POSIX host path.

After this change, full Linux verification passed again. One parallel Windows
regression attempt failed during MSYS initialization (`add_item ... errno 1`),
before the test ran. It was not counted as a product test result. The actual E2E
was allowed to finish, then the six-case Windows regression passed sequentially
using the existing Git Bash executable. No replacement runtime was installed.
Native macOS execution was not tested.

## Actual HAProxy/curl E2E

The repaired entrypoint ran from Windows Git Bash against Docker's Linux engine.
All **26 of 26** declared cases produced passing results, the process exited 0
and its final success summary was present. This includes HTTP/2 multipart,
oversized-body and missing-length checks; multipart case/header evasions;
allowed-path boundaries and dot/encoded-dot traversal; chunked requests and
chunked plus Content-Length; and ordinary requests without a body policy.

The generated golden fixture retained its usual test-only substitutions for
addresses, stats/SPOE paths, container identity and the HTTP/2 test listener.
No golden or appliance policy was relaxed. The actual HAProxy image reported
**2.8.31**; this is the nightly `haproxy:2.8` container scope, not a new Ubuntu

native Windows launch path. It does not establish remote GitHub execution or
approval of all release criteria. CrowdSec and systemd/APT E2E remain separate
follow-ups, as do public ACME/WAN and other appliance checks. No push occurred.
Rollback is a Git revert of f6bc4ad; no appliance rollback is needed for this
test-only change. Ignored local plans, source snapshots and selected logs retain
