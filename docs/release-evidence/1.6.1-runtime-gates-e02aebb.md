Windows amd64. The working tree used the candidate's runtime source inputs
and included later documentation. With `CGO_ENABLED=0`,

## Ubuntu runtime checks

A disconnected Ubuntu 24.04.5 amd64 VMware clone verified a read-only
archive of the exact candidate. It ran Go 1.27.4 with `CGO_ENABLED=0` and
a disposable PostgreSQL 16.15 instance with TCP disabled. The test process
used a private mount namespace and a disposable broker staging directory.

`go test -json -count=1 -p 1 -timeout 9m -skip '^TestGoldenRender$' ./...`
passed 893 top-level tests across 49 packages and skipped 23 top-level
tests. The PostgreSQL migration replay test ran and passed. The golden
render test passed separately. The metrics package also passed with a
long temporary directory to exercise the short socket path fixture.

HAProxy 2.8.30 passed all five checks and 39 subtests in the integration
selection. These covered validation of generated configurations, live
application profiles, GeoIP, path policies and ordered publication rules.
The fixture stopped PostgreSQL and powered off the guest after the run.

The Ubuntu guest had no Node.js or working C compiler. The Windows run
covered the UI-related tests that require Node.js.

## Linux race checks

An isolated Ubuntu 24.04.5 amd64 BuildKit step ran the exact source archive
with Go 1.27.4, GCC 13.3, PostgreSQL 16.15, HAProxy 2.8.30 and Node.js 18.19.1.
The step had only loopback networking and PostgreSQL used a Unix socket.
`go test -race -v -count=1 -p 1 -skip '^TestGoldenRender$' ./... -timeout 9m`
passed 912 top-level tests across 49 packages and skipped four tests. The
separate golden render, all five live HAProxy integration checks and four
root-only tests also passed.

Across two full runs with JSON output, intermittent race warnings appeared
in the login limiter capacity test and the saved APT log size-boundary test.
The captured reports assign both accesses in each warning to the same
goroutine. In a disconnected Ubuntu VMware guest, the Go 1.27.4 race binaries
from the same source passed the login test three times, and the APT test
reported the warning in one of three attempts. A standalone test importing
only the standard library reproduced that APT warning with the same
synthetic 192 MiB workload. The report pairs `bufio.Scanner` filling its
buffer with the subsequent `utf8.Valid` call on that buffer in the same
goroutine. This evidence points to a Go 1.27.4 race detector false positive
in the APT case. The login warning did not reproduce in the guest.

## Native end-to-end checks

Disconnected Ubuntu 24.04.5 amd64 VMware clones ran the fixtures from the
verified archive of `e02aebb`. The native tools included Go 1.27.4, APT
2.8.3, dpkg 1.22.6ubuntu6.6, PostgreSQL 16.15 and nftables 1.0.9-1ubuntu0.1.

- Real APT preserved existing conffiles, blocked fallback after a partial
  configuration failure and installed the checksum-verified fixture DEB.
- Backup publication, restore permissions and backup/restore locking
  passed with disposable configuration and lock directories. The
  PostgreSQL SCRAM test passed in its own network namespace.
- Both native nftables checks passed in a private network namespace. The
  tests verified that confirming the change closes the managed Zabbix port
  and that rollback restores the managed tables while keeping unrelated
  state.
- The private working-directory check for HAProxy passed on retry with
  the read-only `/repo` mount provided by the normal container launcher.
  The initial VMware invocation lacked that fixture mount.

Both guests shut down after the tests. The latest observed [scheduled E2E run](https://github.com/sbezpalov/easy-waf/actions/runs/45319505215)
passed on `e34b562`. These local checks cover the later candidate at the
scopes listed above.
