## AMD64 installation and reboot

A pristine Ubuntu 24.04.5 guest in VMware Workstation had no network adapter.
Easy WAF, HAProxy, PostgreSQL and CrowdSec were absent. The mounted candidate
ISO passed verification as `nobody`. The full profile installed with a
separate, read-only CrowdSec fixture snapshot whose manifest was verified.

The fixture observed a new boot ID after reboot. The API, ACME worker, host
broker, PostgreSQL, HAProxy, nftables, Fail2Ban, CrowdSec and SPOA bouncer were
active. The management readiness endpoint passed HTTPS verification against
the appliance certificate, and HAProxy accepted the live configuration.
All five installed binaries matched the ISO payload and reported `1.6.1`.

MCP was disabled, inactive and had no TCP listener after reboot. The fixture
then provisioned distinct temporary credentials and started MCP on loopback.
The client negotiated MCP revision `2025-11-25`, and `doctor` reported
PostgreSQL ready and HAProxy statistics available through the management API.
The fixture stopped MCP and the guest powered off successfully.

These are local, unsigned artifacts. The ARM64 evidence in this record
covers the build and extracted image.
