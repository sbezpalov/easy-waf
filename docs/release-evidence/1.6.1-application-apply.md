## Confirmed defect and change

Application save and security-mode changes displayed pending Apply even though
the default API path had already applied the mutation. Maintenance claimed a
live change even when `EASY_WAF_NO_AUTO_APPLY=1` disabled automatic Apply.

Successful application mutations now expose the completed automatic Apply
outcome through `X-Easy-Waf-Applied: true` or `false`, without changing their
response JSON. The value comes from the actual apply path, not a second
configuration lookup. Failures do not carry a success outcome. The panel uses
this header for save, security mode and maintenance feedback and pending
indicators; absent headers conservatively leave changes pending. Rejected
changes preserve the form and earlier pending state. No extra Apply request is
sent by the corrected UI handlers.
