# Pristine packaged installation and reboot on VMware

Test date: 2026-11-18, Europe/Moscow. Candidate
`4f64bc4cf2887f028881710ec26beece56f8f7e6` (tree
`aa793259dce0991edccc6853e8b1fd11ba766d25`) was installed on a dedicated
Ubuntu 24.04.5 LTS amd64 VMware guest. The guest used the
[previously authenticated Ubuntu cloud image](1.6.1-pristine-vmware-b5fa4a4.md),
an isolated NAT interface and an SSH host key pinned from its local console.
Cloud-init completed before installation, and the baseline had no product
files or installed easy-waf, HAProxy, PostgreSQL, CrowdSec or Fail2Ban packages.

## Candidate and default installer

The release workflow's preflight and build steps ran locally from the exact
source tree. Artifact checks covered SHA-256, ELF architecture, DEB metadata,
binary equality between DEB and tarball, shell line endings and the amd64
version output for all four packaged commands.

The unmodified installer provisioned dependencies and installed the checked
local amd64 DEB. It exited successfully with local PostgreSQL 16.15, HAProxy
2.8.30, CrowdSec 1.8.2 and systemd 255.4. Both the package and the management
API reported 1.6.1. Four installed executables and three running daemon
executables matched the package. The migration ledger contained 28 records,
ending at 028. The backup timer was enabled and active before the first
reboot, with no installer rerun.

Management HTTPS verified against the fixture certificate. One-time
enrollment succeeded, consumed the secret and rejected replay with HTTP 409.
An authenticated CrowdSec decisions read passed. Two authenticated API Apply
cycles served the expected marker from a loopback origin and returned healthy
HAProxy stats. A Windows client independently received the marker through NAT.

## Reboot and test scope

A real reboot changed the boot ID from
`0d66412c-14fa-4652-8e3c-ee31f32df934` to
`bd243630-34ea-4f8d-8b91-425359417032`. The first verifier reached SSH while
management HTTPS was still starting and received a connection refusal. The
API became ready on that boot without a service restart. The verifier then
confirmed, before any new Apply, that the HTTP publication returned its
marker and that saved and applied edge generations matched.

The backup timer, ten checked services, candidate payload, schema, CrowdSec
read, two further Apply cycles and HAProxy stats passed. Authenticated smoke
returned 20 passes, 0 failures and 2 skips both before and after reboot.
The skips were for the legacy admin token and optional MMDB. The independent
Windows client received the marker again.

The test guest was powered off with private fixture data retained on its disk.
PVE and the VMware restore clone were outside the scope. This run exercises
the amd64 package on Ubuntu and HTTP over NAT. Signing, arm64 execution,
public certificate issuance and browser-driven Apply require separate evidence.
