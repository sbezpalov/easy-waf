## Advisory, dependency scope and review

[GO-2026-5932](https://pkg.go.dev/vuln/GO-2026-5932) marks the old parent
`golang.org/x/crypto` module affected because it contains unmaintained OpenPGP.
The separate `golang.org/x/crypto/openpgp` module remains unsafe; splitting it out
is not a repair of OpenPGP itself. Easy WAF did not import those packages.

The update selects the official tagged x/crypto v0.59.0, which no longer includes
OpenPGP in the parent module. No OpenPGP submodule, replacement implementation or
scanner suppression was added. Its required Go 1.26 fits the existing Go 1.27.4;
no Go runtime was installed or upgraded.

Required selected versions changed as follows:

| Locked module | Before | After |

| x/crypto | 0.58.0 | 0.59.0 |
| x/sys | 0.49.0 | 0.50.0 |
| x/sync | 0.24.0 | 0.25.0 |
| x/text | 0.43.0 | 0.44.0 |

MVS also selected newer x/term, x/tools and x/mod through upstream requirements;
they were not added to go.mod and were absent from the audited Linux/amd64
appliance package list. No unrelated module version changed. Normal Go checksum
verification and `go mod verify` passed; tidy only removed obsolete sums.

Downloaded source comparison found the three used crypto packages (`bcrypt`,
`blowfish`, `ocsp`) unchanged. For the actual Linux/amd64 selected source files,
review identified changes in Unix directory-entry handling, an additional ioctl
helper, a short-credentials bounds check and the underscore-aware language-tag
size guard. No caller API adaptation was needed. This source review is not a
claim that all upstream packages or architectures were byte-identical.
