## Independent WAN retry — 2026-11-16

The operator selected HTTP-01 for this deployment. CloudNS was identified as the
DNS provider, but no DNS API credentials or DNS/NAT changes were needed.

A fresh, uniquely addressed test backend was published using the existing renewed
production certificate. Its systemd-owned test window was bounded to 30 minutes;
cleanup refreshed the operator session and removed only the temporary application.
No further certificate issuance or renewal was requested.

- From the VM, trusted TLS and exact HTTP 200 marker passed via loopback, LAN,
  public hostname and public IPv4. Each served the same expected leaf certificate.
- Native Windows curl preserved chain, hostname and revocation checks. The LAN
  request with public-name SNI returned the exact marker over trusted TLS. The
  public-name request timed out before TCP connect; its cause was not established.

  confirmed `easy-waf-wan-ok` without a certificate warning. This is the independent
  browser/WAN observation; the earlier expired-window result is not used to infer
  an appliance failure.

  `X-Forwarded-For` matched the address in HAProxy's log for the unique URL.
  Seven backend requests matched seven access-log entries after accounting for
  HTTP/2 request-line form; one distinct global client matched. The actual client
  address and selected raw logs remain private on the VM.
- The stop marker completed the owned task successfully (exit 0, no remaining
  main PID), removing the test application and stopping its backend. All ten
  checked appliance services remained active, installed binary comparisons still
  matched the candidate DEB, HAProxy master ran as `haproxy`, and trusted management
  readiness returned HTTP 200.
