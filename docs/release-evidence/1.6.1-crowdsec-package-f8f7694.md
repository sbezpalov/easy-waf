## Host resource failures and recovery

The first package invocation failed during PowerShell initialization with a
stack overflow; no log/container was created. A second observer died with
`Out of memory`. Subsequent process/container inspection confirmed no Go/Bash
children or lifecycle fixture remained, and the log contained no test assertions.
Neither attempt was counted as a passing gate or a product failure.

Windows then had about 0.9 GiB free virtual memory. Only the owned dev clone was
gracefully powered off to free resources. The successful repeat used native Go
`-p=2`, `GOMAXPROCS=2` and `GOGC=50`; no test was excluded. Windows security
settings, user applications, other VMs and host runtimes were not changed.

To return the dev clone without exhausting host memory, its powered-off VMX had
only `memsize` changed from 4096 to 2048 MiB, the documented light-lab minimum.
The original configuration, proposed diff and rollback instructions were retained
locally before editing. RAM can be restored to 4096 MiB while the clone is off
and the host has headroom; preserve all other current VMX fields. The clone was
started without a guest window and remains running. The original source VM
remained off and the PVE appliance was untouched.
