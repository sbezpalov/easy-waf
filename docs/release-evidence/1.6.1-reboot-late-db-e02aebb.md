# Published HTTPS, PostgreSQL recovery and reboot — e02aebb

On 2026-11-24, a new Ubuntu 24.04.5 amd64 VMware guest installed the
[verified e02aebb ISO](1.6.1-packages-e02aebb.md) without a network adapter.
Authenticated About reported 1.6.1 and
`e02aebbe36ea3ca52e3cb066e8a9f5f05883ab5a`. The test used one temporary
loopback publication and an explicitly trusted local certificate.

The fixture stopped the local PostgreSQL cluster after recording the
working route. The management readiness endpoint returned 503 and a new
trusted HTTPS request to the published route returned the expected 200 and
body. API and ACME were started with PostgreSQL still down. Each retried
at least twice, and the route continued serving HTTPS. When PostgreSQL
returned, both services recovered without a manual service restart and
management readiness returned to 200.

The same guest then rebooted. The boot ID changed, the expected units
were active, and the management API authenticated the test operator at the
same revision. The application and certificate records were present.
The certificate matched its pre-reboot SHA-256, and a verified HTTPS
request returned the same leaf and exact response. The fixture removed
the temporary publication and certificate records, revoked its session
and powered off the guest.

The PostgreSQL outage and service-start recovery were exercised before
the actual reboot. The fixture used a local test route with no WAN traffic.
