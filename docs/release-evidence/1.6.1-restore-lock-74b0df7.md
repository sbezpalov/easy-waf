## Defects and regression gates

The preceding installed 677a499 package reproduced two defects: restore stopped
the control plane before rejecting a missing archived env, and restore could
overlap a backup holding its directory lock. These negative controls used the
actual installed commands and real tar/flock in a private mount namespace;
only database/service leaves were mocked and `/etc/easy-waf` was private tmpfs.
The appliance's real data and services were untouched by these controls.

Restore now requires `flock`, acquires backup's nonblocking configuration-directory
lock before extraction and retains it through service startup. It checks missing
or empty archived `DATABASE_URL` before stopping services. Manual service starts
and factory reset remain outside this lock and must not overlap either operation.

The regression fixture checks missing/empty env and missing locking capability
without database/service access. Backup and restore holders are gated during
database work and writer startup; both backup and restore competitors must fail
on the lock without reaching those leaves (eight rejection cases). The successful
holder then finishes and releases its lock. This passed against the final source,
the extracted amd64 package and the actual installed operator commands.

Full Linux `make verify`, existing backup-publication and restore-permissions /
symlink regressions passed for the exact staged tree committed above. Native
Windows Git Bash syntax checks and ShellCheck 0.11.0 also passed. Docker required
a previously authorized Desktop restart after image metadata and container
creation stalled; the subsequent complete verification and builds finished
successfully. No Go source or dependencies changed; no new race or vulnerability
scan is claimed. macOS was not tested.
