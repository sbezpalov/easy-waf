## Confirmed configuration issue and repair

The certificate form initially displayed an empty ACME email and staging enabled.
A read-only authenticated settings request confirmed these were the actual
stored global values, not a form-population bug. The existing public certificate
was production/ready, but that alone did not establish renewal readiness:
`worker.runOnce` in `cmd/easy-waf-acmed/main.go` returns idle when global ACMEEmail
is empty, and issuance chooses staging when either staging flag is true.

The repair used the previously operator-supplied contact and production mode
through the ordinary password-confirmed API PATCH. Complete before/after settings
were retained root-private on the VM beside the existing matched appliance
checkpoint. The verified settings diff contained exactly `acme_email` and
`acme_staging`; all other settings and complete application/certificate objects
were unchanged. No contact address, token or private configuration is included
in this report.

Before restarting the ACME worker, the probe required exactly one ready
production certificate with over 30 days left, so the repair did not deliberately
make a certificate due. Only `easy-waf-acmed.service` was restarted. It was active
after restart; subsequent API reads confirmed a configured contact and global
staging=false. No forced issue/renew request was sent, and certificate objects
and the served leaf remained unchanged.

After another native browser reload, the ACME form displayed the saved contact
and an unchecked staging box. The separate final appliance probe again passed
candidate binary hashes, unchanged application/certificate objects, exact trusted
HTTPS/backend response and active core services.

Recovery artifacts remain private on the VM: original global settings plus the
matched pre-alignment appliance backup and previous package. Exact return to an
empty email requires the documented matched restore if needed: API merge semantics
preserve an existing contact when an empty email is submitted. No such rollback
was necessary. Old checkpoints intentionally retain the earlier configuration;
restoring them also restores those ACME defaults, so recheck ACME readiness after
any recovery.
