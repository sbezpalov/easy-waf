## Build and integrity

The bundle builder ran in Ubuntu 24.04 arm64 userspace under Docker emulation
and used xorriso 1.5.6. APT used the package archive from the verified
[77d73e0 arm64 ISO](1.6.1-offline-iso-77d73e0.md) through a loopback server
inside the build container. The empty-state APT solve passed. The image
contained 178 packages, all arm64 or architecture-independent, including
CrowdSec 1.8.2, its SPOA bouncer 0.4.0, HAProxy 2.8.30 and PostgreSQL 16.15.

The extracted ISO passed `install.sh --verify-only`. The release verifier
matched both copies of the DEB and its inner checksum manifest to the exact
candidate DEB. Windows independently matched the ISO and DEB SHA-256 values.

## Clean install in QEMU

QEMU 8.2.2 booted the verified Ubuntu 24.04.5 arm64 cloud image with no
network adapter and a fresh disk overlay on Linux storage. The guest had
only loopback and no external IPv4 or IPv6 route. The ISO was mounted
read-only at `/mnt/Offline image #1%`. The installer rejected the missing
CrowdSec snapshot before provisioning. With the separately mounted,
checksum-verified snapshot, its log recorded installation completion and
systemd reported the Easy WAF services and backup timer started.

The test harness then failed its comparison of the entire `/etc/apt`
tree. Read-only inspection confirmed that PostgreSQL's
`pg_updateaptconfig` had generated `02autoremove-postgresql` as part of
normal package configuration and that cloud-init rewrote `ubuntu.sources`
before the test began. The system APT indexes matched the pristine image,
the test's host APT hook did not run, and CrowdSec's temporary bootstrap
files were gone.

## Reboot and runtime

A second QEMU boot used a copy of the installed disk with the same offline
ISO, no network adapter and the snapshot media disconnected. Ten services
and timers were active. PostgreSQL reported schema 029, CrowdSec LAPI was
reachable and its Linux, HAProxy, SSH and PostgreSQL collections were
enabled. HAProxy accepted its live configuration and the management
readiness endpoint passed HTTPS verification with the guest certificate.
The four installed Easy WAF binaries and all three daemon process
executables matched the arm64 DEB byte for byte.

Repeating installation without the snapshot succeeded. The checksums of
the recorded system APT files, the CrowdSec configuration and local
override, the acquisition file and the Hub index remained identical.
LAPI remained reachable, and the guest reported success and powered off.

This evidence covers the local unsigned arm64 ISO in QEMU system
emulation. Native arm64 hardware and the signed release workflow remain
outside this run.
