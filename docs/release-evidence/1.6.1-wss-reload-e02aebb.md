# Installed WSS idle and Apply/reload continuity — e02aebb

On 2026-11-24, a fresh disconnected Ubuntu 24.04.5 amd64 VMware guest
installed the [verified e02aebb ISO](1.6.1-packages-e02aebb.md).
Authenticated About reported 1.6.1 and
`e02aebbe36ea3ca52e3cb066e8a9f5f05883ab5a` before the WSS test.

The test used a dedicated loopback backend that echoes WebSocket frames, a
local SAN certificate and a temporary publication using the Home Assistant
profile. The client waited for port 443 after creating the application,
validated TLS and the exact leaf, received HTTP 101 and verified the
first text-frame echo.

While that connection was idle, the authenticated and password-confirmed
management API applied the configuration. A new HAProxy worker appeared
under the same master, and the original worker stayed alive while serving
WSS. A separate HTTPS connection returned the expected backend marker with
HTTP 200. API stats and the local stats socket both answered.

The original TLS/WebSocket connection echoed a second frame after 62.0
seconds without application traffic, beyond the configured ordinary HTTP
client timeout of 50 seconds. The peer acknowledged a normal close
with code 1000. The fixture deleted the application and certificate
metadata, revoked the test session and powered off the guest.

This run covered installed-appliance WSS transport and reload on amd64.
Public WAN access, ACME trust and an authenticated Home Assistant
Companion session remain outside its scope.
