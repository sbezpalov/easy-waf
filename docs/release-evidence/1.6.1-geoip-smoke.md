# GeoIP smoke failure reporting

Date: 2026-11-17. Follow-up to the
[9cfc841 VMware restore](1.6.1-restore-9cfc841.md).

The dedicated clone uses the IPinfo provider without a local MMDB. A fresh
authenticated uncached API lookup returned 200, while an independent request to
the same public IPinfo endpoint returned HTTP 429. Recent API logs also contained
an IPinfo HTTP 429 error. This establishes upstream rate limiting on the stand;
it does not prove that every earlier 502 had the same cause.

The smoke script incorrectly treated every non-200 GeoIP lookup as skipped
coverage, including authentication errors and provider/network failures. It now
records a failed check and exits nonzero through the existing failure summary.
The error reports the HTTP status and directs the operator to provider/database
availability; it does not print the upstream response body. Optional MMDB upload
input and absent authentication remain distinct skipped checks.

Verification:

- The existing isolated HTTP/systemd fixture now covers successful lookup and
  HTTP 502, HTTP 401 and transport-status 000. It passed under Windows Git Bash
  5.3.15 and Ubuntu 24.04.5 Bash. The updated test rejected the old script at the
  HTTP 502 case and passed again after restoring the fixed script.
- ShellCheck 0.11.0 returned zero with an empty JSON diagnostic list for both
  changed scripts, using the scripts directory to resolve the shared parser.
  Bash syntax checks passed on Ubuntu. Native Git Bash required execution outside
  the sandbox because MSYS object creation was denied inside it.
- One real run of the fixed smoke script against the clone's installed 9cfc841
  package passed **19 checks, 0 failed, 2 skipped**. Skips were the absent
  separate admin token and optional MMDB upload input. GeoIP lookup passed in
  that run; continued upstream availability is not claimed.

No provider settings, credentials, dependency binaries or PVE state changed.
The clone's dedicated account was used for smoke's normal login/logout checks.
Full diagnostic and smoke logs remain on that VM. Rollback is reverting the
smoke-script commit; no database or package rollback is needed.
