# Offline 1.6.1 installation with clock skew

The first arm64 installation of `e02aebb` used a fresh Ubuntu 24.04.5
guest with no network adapter. The verified ISO mounted read-only and
the CrowdSec snapshot matched its manifest. APT refused the local
repository because the `Release` timestamp was over an hour ahead of the
guest clock. This stopped full-profile installation during CrowdSec
bootstrap.

The fix in `dfc3adaa2ad6945add468fca88ebd9de0aa569ec` sets `check-date=no`
on the temporary `file:` source created after bundle verification. The
installer clears that APT workspace on exit. A real Ubuntu APT regression
test uses metadata dated a day in the future. The previous installer
failed at index acquisition and the fixed installer retrieved the
fixture package and matched its bytes. ShellCheck, the release-notes
tests and the repository Linux-artifact checks also passed.

## amd64 appliance installation

A fresh VMware guest without a network adapter verified the exact ISO
and installed the full profile with the CrowdSec snapshot. After reboot,
it confirmed ten active units, schema 029, trusted readiness, CrowdSec
LAPI, a valid HAProxy configuration, byte-identical installed and running
binaries, authenticated About and the shipped read-only smoke checks.
The fixture checked the Git commit date against About after correcting a
stale expected date from the previous candidate.

Repeat installation without a mounted snapshot preserved CrowdSec and
the system APT sources and indexes. The shipped firewall repair toggled
Zabbix while the existing service, management guard and unrelated table
stayed active. Installed backup and restore recovered synthetic database,
state and configuration values, modes, ownership and trusted readiness.
The guest shut down successfully.

## arm64 appliance installation

A fresh Ubuntu 24.04.5 arm64 guest booted under QEMU 8.2.2 and UEFI with
loopback only and the exact ISO mounted read-only. The guest clock predated
the verified APT `Release` metadata. Installation without the CrowdSec
snapshot was rejected before provisioning. With the verified snapshot,
the full profile installed and preserved the system APT sources and indexes.

After reboot, the fixture checked ten active units, schema 029, trusted
HTTPS, CrowdSec LAPI, a valid live HAProxy configuration and the exact bytes
of the installed binaries and the three running daemons. An authenticated
About request returned the expected source revision, commit date, component
versions and attribution. Reinstalling with the snapshot unmounted preserved
the CrowdSec files and system APT sources and indexes. The guest powered off
and the QEMU fixture exited successfully.
