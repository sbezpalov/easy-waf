# Easy Home WAF 1.6.1 pre-tag verification

On 2026-11-18 the local release build used
`e066d3ff0f7009ec876c15a528cb0cc2adb7328d`. The tag `v1.6.1` was
absent on origin when checked. The release preflight selected the single
1.6.1 changelog section and matched the proposed tag to `VERSION`.

The first workflow replay on `75eb5d9` showed that APT interpreted the
relative DEB path as package/release syntax. The fix passes an absolute
path and adds a test that exercises the builder up to its APT invocation.
The shell check, full `make verify` and installer syntax checks passed on
the fixed commit.

## Source and appliance checks

- The Linux race suite passed 864 top-level tests in 49 packages with zero
  failures or test skips. It used Ubuntu 24.04 amd64, Go 1.27.4, GCC 13.3.0,
  HAProxy 2.8.30, Node 18.19.1 and PostgreSQL 16.16 on an internal Docker
  network without published ports. Vet, golangci-lint, separate golden
  tests, live HAProxy tests and govulncheck against the public Go
  vulnerability database passed on `75eb5d9`. The fix changed shell
  build/test code and changelog text. All ten Go executable digests also
  matched across both builds.
- The release workflow and Web UI Go tests passed on Windows amd64 with
  Go 1.27.4 and Node 26.13.1. macOS was outside this run.
- All six local E2E launchers passed on `e066d3f`: installer conffiles,
  HAProxy working directory, backup publication, HAProxy body policy,
  CrowdSec and the seven-case systemd/APT package lifecycle.
- Prior boots, installs and reinstallation are recorded in the
  [amd64 VMware and ARM64 QEMU report](1.6.1-offline-iso-3ef58b7.md).
  Public HTTP-01 issuance, renewal and mobile WAN access are covered by
  the [PVE ACME record](1.6.1-public-http01.md). The
  [mobile CrowdSec record](1.6.1-pve-ac05-mobile.md) confirms AC-05 on PVE.
  Those appliance results retain their recorded build scope.

## Remaining release steps

1. Push the selected `main` commit and confirm CI for that commit. The
   latest observed [push CI](https://github.com/sbezpalov/easy-waf/actions/runs/44257023674)
   was on `c58f018` and the latest observed
   [GitHub nightly E2E](https://github.com/sbezpalov/easy-waf/actions/runs/44230359345)
   was on `9a7c2f9`.
2. Approve the release commit and date. The changelog stays marked
   Unreleased until the release date is set. The operator owns the tag and
   push.
3. After tagging, confirm the GitHub Release workflow verifies both signed
   ISOs and publishes the complete asset set. Verify the downloaded Sigstore
   bundles against the exact tagged workflow identity and check the signed
   candidate on the appliance. Local artifacts carry checksums only.

DNS-01 is deferred by the operator. The HTTP-01 evidence remains the
basis for the public TLS check in this release scope.
