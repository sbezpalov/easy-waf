# Packaged backup recovery checks for 2bdeca3

Source `2bdeca31a2d8e010b694d3fce4ad2b65cc74ab4f`, tree
`b0ceba0b109e7990c8fff5c1e2c6fb4e54df4f3d`. The release workflow preflight
and build steps produced unsigned amd64 and arm64 packages and tarballs.
Their checksums, ELF architectures, package metadata, tar and DEB payloads,
shell line endings and amd64 CLI versions passed inspection. The installed
amd64 DEB had SHA-256
`a98ee7edcfb37389c06daf17d98ba6d59fa662b99f591b287cbe39b2ec5e17ac`.
The arm64 artifacts were inspected without running them.

The independent Ubuntu 24.04.5 VMware clone installed the package through APT
after taking a matched pre-upgrade archive. The installed backup and restore
script hashes matched the source. The new backup command then created a
matched private archive and the strict runtime checks confirmed the original
settings, application and certificate records, selected file hashes,
HAProxy revision and generation 7.

The installed command passed both real systemd failure exercises:

- ACME refused a manual stop. Backup returned 1 before entering the
  `pg_dump` stage and left the existing archive byte-identical. The strict
  runtime baseline passed after the test override was removed.
- ACME refused a manual start after backup. The command returned 1, reported
  the path of the complete archive and did not print the completion message.
  The private archive had mode `0600`. After removing the override and
  starting ACME, the strict probe passed. The matching packaged restore then
  read that specific archive, returned zero and confirmed Apply.

After restore, the same schema 028, state, services, permissions, HAProxy
stats, broker and trusted HTTPS passed the strict probe. Both test unit
overrides were absent, the backup timer was active and no failed unit was
listed. An independent Windows client verified the expected certificate and
exact HTTPS response.

The old DEB and pre-upgrade archive remain available together for rollback.
Private archives and logs remain on the clone in
`acceptance-work/backup-2bdeca3`. Host build records and drivers are in
`.ai/artifacts/backup-2bdeca3/`. This is installed behavior evidence for the
backup lifecycle on amd64. Signed-release acceptance remains open.
