# Offline 1.6.1 firewall directory permissions

On a fresh Ubuntu 24.04.5 amd64 VMware guest, the `2aa81a2` offline installer
ran under `umask 077`. After reboot, both managed nftables tables were live.
The time zone change, audit and host-local journal display also passed through
the installed API. The firewall API could not return the managed rules file.
An isolated clone showed that `/etc/nftables` was `root:root` with mode `0700`.
Both files had mode `0644`, but the `easy-waf` service account could not
traverse the directory.

Commit `3463cfd797bc1ac9614a0ccf45b61f6c219b4711` creates a missing directory
with the same permissions as a normal installation under `umask 022`. It
preserves an existing directory's permissions. The installer regression test
failed on the old helper and passed on the fixed helper under `umask 077`.

## Direct amd64 package upgrade

An isolated Ubuntu 24.04.5 VMware clone installed the published 1.6.0 DEB
and reached trusted HTTPS readiness with schema 019. An offline APT upgrade
to the exact `3463cfd` DEB reached schema 029 and preserved a database marker,
the management environment file and the management certificate. All four
installed executables matched the package and reported 1.6.1. The three
running daemon executables also matched. HAProxy validation, trusted HTTPS
readiness and the installed backup and restore script comparisons passed.

## Installed firewall access and time zone

The amd64 ISO completed a clean full-profile installation under `umask 077`
and rebooted with schema 029, trusted HTTPS, working CrowdSec LAPI and the
expected running binaries. The installed API changed the host time zone,
recorded the change in audit and returned journal timestamps with the new
UTC offset while the API process kept the same PID. The fixture restored the
original zone through the same endpoint.

The new directory was `0755` and the managed rules file was `0644`. The API's
service account could read the file, and an authenticated request returned the
managed rules. A clone of the resulting appliance was enrolled with a new
synthetic operator. Its installed API confirmed one change and rolled back a
second after the confirmation window expired. The managed live table and the
management guard matched their baseline, the pending operations list was
empty and HTTPS readiness stayed healthy. The earlier native regression
covered a collected rollback unit. The installed API run observed a loaded
rollback unit.

The same clone detected two synthetic Zabbix packages and reported their exact
installed version in About. It enabled, started, restarted, stopped and
disabled both units through the authenticated host API. Each service and
package row disappeared after the fixture purged its package. The clone
powered down successfully. A separate fresh-install retry stopped at an
intermittent CrowdSec startup failure before these checks. The isolated
system journal showed CrowdSec 1.8.2 terminating with `SIGSEGV` during
`k8s.io/klog/v2/internal/buffer.init`, before the agent started serving
requests. The verified snapshot receipt remained available for a retry.

A follow-up on a disconnected clone of that failing guest exercised the
updated bootstrap script against the original verified ISO and snapshot. The
fixture injected one failed restart request and let the second request run
through systemd. CrowdSec reached local LAPI readiness, the receipt was
removed and the fixture observed zero APT invocations. POSIX tests covered
successful recovery and the limit of three failed restart attempts.

## arm64 offline appliance installation

A disconnected Ubuntu 24.04.5 guest under QEMU 8.2.2 booted from the
`3463cfd` media with its clock behind the APT metadata. It rejected a missing
snapshot before provisioning, installed with the verified snapshot and
rebooted successfully. The ten required units, schema 029, trusted HTTPS,
CrowdSec LAPI, live HAProxy configuration and exact installed and running
binaries all passed verification. Authenticated About reported the source
revision, commit date and installed components.

The installed API passed the time zone, audit, journal offset, nftables
confirmation, automatic rollback and management guard checks. It also
detected and managed both synthetic Zabbix services and reported their
installed package versions. A repeat installation with the snapshot
unmounted preserved CrowdSec and system APT files. The guest powered off
and the emulator fixture exited successfully.
