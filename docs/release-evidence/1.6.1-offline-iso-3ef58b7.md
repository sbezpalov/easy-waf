## Build and integrity

The default CrowdSec profile was built using the repository script on
Ubuntu 24.04 amd64 with APT 2.8.3, xorriso 1.5.6 and the fingerprint-pinned
CrowdSec package repository. The ISO contains 178 indexed packages,
including Easy WAF, HAProxy 2.8.30, PostgreSQL 16.15, CrowdSec 1.8.2 and
the HAProxy SPOA bouncer 0.4.0.

The first build from `dd27d74` reproduced an unsatisfied `util-linux`
dependency. Commit `cc196b9` includes the verified Easy WAF DEB in the
initial dependency solve.
The next build passed the independent empty-state APT solve using only its
local repository. On a clean Ubuntu guest, the ISO installation then exposed
the host's `/etc/os-release` replacing the bundle version. The handoff test
reproduced the failure and passed after `3ef58b7` preserved the package
version. `make verify` passed for both fixes.

## Installation on clean VMware

The unsigned ISO was mounted read-only on a fresh Ubuntu 24.04.5 amd64
guest. Easy WAF, HAProxy, PostgreSQL and CrowdSec were absent before
installation. The installer started with the guest's Ethernet interface
down. The fixture observed only loopback and no IPv4 or IPv6 external
route. It used the ISO's temporary local APT configuration.

APT configured the verified Easy WAF 1.6.1 DEB. Provisioning then failed in
the upstream CrowdSec 1.8.2 package. Its
[maintainer script](https://github.com/crowdsecurity/crowdsec/blob/v1.8.2/build/debian/postinst)
runs `cscli hub update` during configuration. The guest could not resolve
`version.crowdsec.net`, dpkg reported `half-configured` for CrowdSec, and
the SPOA bouncer remained inactive. The installer returned exit 1.
The guest was powered off after collecting these observations.

The full CrowdSec profile remains blocked on air-gapped installation.
Complete appliance startup, the base profile, arm64 and signed ISO
publication were outside the verified result in this run.

## Follow-up with a locally staged CrowdSec snapshot

The same amd64 guest resumed from the failed installation. With only
loopback available, the original CrowdSec DEB read an official Hub index
with embedded content through the vendor CLI's local URL configuration.
The index alone was insufficient. Adding all 21 data files identified from
the detected collections was also insufficient because the updater still
attempted HTTP HEAD requests to validate the data. [CrowdSec Hub configuration](https://github.com/crowdsecurity/crowdsec/blob/v1.8.2/pkg/csconfig/cscli.go) [Data freshness logic](https://github.com/crowdsecurity/go-cs-lib/blob/v0.0.25/downloader/download.go)

The connected test builder generated the cache using CrowdSec CLI
`v1.8.2-3d369d64`, the same upstream revision as the DEB. The cached index
matched the previously verified bytes. The captured archive SHA-256 was
`913b3dad622eb98b061bf563ceffdb45a3f1e607b0aca0713643c91d39dc4d10`.
The files were retained as private test artifacts.

On the guest, the vendor CLI generated acquisition configuration from the
saved detection plan. The unmodified DEB then configured with the local
index and the upstream `CROWDSEC_SETUP_UNATTENDED_DISABLE` setting. LAPI
started while the Ethernet interface was down. The fixture copied 99
checked regular files into the Hub and data directories. The vendor CLI
created the activation links and enabled the Linux, HAProxy, SSH and
PostgreSQL collections from that cache. CrowdSec configuration validation
and LAPI passed. [CrowdSec unattended option](https://github.com/crowdsecurity/crowdsec/blob/v1.8.2/cmd/crowdsec-cli/clisetup/unattended.go)

Rerunning the same read-only ISO after that manual staging returned zero
with the Ethernet interface down and the host APT sources unchanged.
Easy WAF, HAProxy, PostgreSQL, nftables, Fail2Ban, CrowdSec/SPOA and the
backup timer were active. The installed and running Easy WAF binaries
matched the DEB. Schema 028, trusted management readiness, HAProxy
configuration and LAPI passed in a separate loopback-only verification.
The guest was then powered off.

## Private ISO with an embedded snapshot

Source commit `a28ec6998ddd99710f8bfff570586321013a5306` built the private
amd64 ISO on Ubuntu 24.04 with xorriso 1.5.6. It used the same verified
Easy WAF DEB listed above. The isolated APT solve passed with 178 indexed
packages, including CrowdSec 1.8.2. The builder checked that release
against the snapshot metadata before staging it.

The resulting `easy-waf_1.6.1_offline_ubuntu24.04_amd64_private.iso` had
SHA-256 `8c8efd6fc2189a7a1e7e82b394039b44e66cf38479d14690286e7501e8d9385a`.
Windows reported the same hash after copying the ISO out of the Linux
container. Extraction with xorriso and `install.sh --verify-only` passed.
The outer manifest covered the embedded manifest, which matched the
original byte for byte. Its 101 listed files all passed SHA-256 verification.
The extracted snapshot contained only those files and the manifest.

Fresh offline installation still needs automatic activation of the embedded
snapshot and a check that upgrades preserve existing CrowdSec configuration.
This build verifies delivery and integrity. The cache contains GeoLite
databases and needs a distribution-rights check before inclusion in any
public ISO. [MaxMind GeoLite licensing guidance](https://support.maxmind.com/knowledge-base/articles/sell-or-display-data-from-geolite-databases-and-web-services)
