## Build and integrity

The default CrowdSec profile was built using the repository script on
Ubuntu 24.04 amd64 with APT 2.8.3, xorriso 1.5.6 and the fingerprint-pinned
CrowdSec package repository. The ISO contains 178 indexed packages,
including Easy WAF, HAProxy 2.8.30, PostgreSQL 16.15, CrowdSec 1.8.2 and
the HAProxy SPOA bouncer 0.4.0.

The first build from `dd27d74` reproduced an unsatisfied `util-linux`
dependency. Commit `cc196b9` includes the verified Easy WAF DEB in the
initial dependency solve.
The next build passed the independent empty-state APT solve using only its
local repository. On a clean Ubuntu guest, the ISO installation then exposed
the host's `/etc/os-release` replacing the bundle version. The handoff test
reproduced the failure and passed after `3ef58b7` preserved the package
version. `make verify` passed for both fixes.

## Installation on clean VMware

The unsigned ISO was mounted read-only on a fresh Ubuntu 24.04.5 amd64
guest. Easy WAF, HAProxy, PostgreSQL and CrowdSec were absent before
installation. The installer started with the guest's Ethernet interface
down. The fixture observed only loopback and no IPv4 or IPv6 external
route. It used the ISO's temporary local APT configuration.

APT configured the verified Easy WAF 1.6.1 DEB. Provisioning then failed in
the upstream CrowdSec 1.8.2 package. Its
[maintainer script](https://github.com/crowdsecurity/crowdsec/blob/v1.8.2/build/debian/postinst)
runs `cscli hub update` during configuration. The guest could not resolve
`version.crowdsec.net`, dpkg reported `half-configured` for CrowdSec, and
the SPOA bouncer remained inactive. The installer returned exit 1.
The guest was powered off after collecting these observations.

The full CrowdSec profile remains blocked on air-gapped installation.
Complete appliance startup, the base profile, arm64 and signed ISO
publication were outside the verified result in this run.
