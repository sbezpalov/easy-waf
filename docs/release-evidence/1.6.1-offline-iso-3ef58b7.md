## Build and integrity

The default CrowdSec profile was built using the repository script on
Ubuntu 24.04 amd64 with APT 2.8.3, xorriso 1.5.6 and the fingerprint-pinned
CrowdSec package repository. The ISO contains 178 indexed packages,
including Easy WAF, HAProxy 2.8.30, PostgreSQL 16.15, CrowdSec 1.8.2 and
the HAProxy SPOA bouncer 0.4.0.

The first build from `dd27d74` reproduced an unsatisfied `util-linux`
dependency. Commit `cc196b9` includes the verified Easy WAF DEB in the
initial dependency solve.
The next build passed the independent empty-state APT solve using only its
local repository. On a clean Ubuntu guest, the ISO installation then exposed
the host's `/etc/os-release` replacing the bundle version. The handoff test
reproduced the failure and passed after `3ef58b7` preserved the package
version. `make verify` passed for both fixes.

## Installation on clean VMware

The unsigned ISO was mounted read-only on a fresh Ubuntu 24.04.5 amd64
guest. Easy WAF, HAProxy, PostgreSQL and CrowdSec were absent before
installation. The installer started with the guest's Ethernet interface
down. The fixture observed only loopback and no IPv4 or IPv6 external
route. It used the ISO's temporary local APT configuration.

APT configured the verified Easy WAF 1.6.1 DEB. Provisioning then failed in
the upstream CrowdSec 1.8.2 package. Its
[maintainer script](https://github.com/crowdsecurity/crowdsec/blob/v1.8.2/build/debian/postinst)
runs `cscli hub update` during configuration. The guest could not resolve
`version.crowdsec.net`, dpkg reported `half-configured` for CrowdSec, and
the SPOA bouncer remained inactive. The installer returned exit 1.
The guest was powered off after collecting these observations.

This stock ISO stopped during air-gapped CrowdSec configuration.
Complete appliance startup, the base profile, arm64 and signed ISO
publication were outside the verified result in this run.

## Follow-up with a locally staged CrowdSec snapshot

The same amd64 guest resumed from the failed installation. With only
loopback available, the original CrowdSec DEB read an official Hub index
with embedded content through the vendor CLI's local URL configuration.
The index alone was insufficient. Adding all 21 data files identified from
the detected collections was also insufficient because the updater still
attempted HTTP HEAD requests to validate the data. [CrowdSec Hub configuration](https://github.com/crowdsecurity/crowdsec/blob/v1.8.2/pkg/csconfig/cscli.go) [Data freshness logic](https://github.com/crowdsecurity/go-cs-lib/blob/v0.0.25/downloader/download.go)

The connected test builder generated the cache using CrowdSec CLI
`v1.8.2-3d369d64`, the same upstream revision as the DEB. The cached index
matched the previously verified bytes. The captured archive SHA-256 was
`913b3dad622eb98b061bf563ceffdb45a3f1e607b0aca0713643c91d39dc4d10`.
The files were retained as private test artifacts.

On the guest, the vendor CLI generated acquisition configuration from the
saved detection plan. The unmodified DEB then configured with the local
index and the upstream `CROWDSEC_SETUP_UNATTENDED_DISABLE` setting. LAPI
started while the Ethernet interface was down. The fixture copied 99
checked regular files into the Hub and data directories. The vendor CLI
created the activation links and enabled the Linux, HAProxy, SSH and
PostgreSQL collections from that cache. CrowdSec configuration validation
and LAPI passed. [CrowdSec unattended option](https://github.com/crowdsecurity/crowdsec/blob/v1.8.2/cmd/crowdsec-cli/clisetup/unattended.go)

Rerunning the same read-only ISO after that manual staging returned zero
with the Ethernet interface down and the host APT sources unchanged.
Easy WAF, HAProxy, PostgreSQL, nftables, Fail2Ban, CrowdSec/SPOA and the
backup timer were active. The installed and running Easy WAF binaries
matched the DEB. Schema 028, trusted management readiness, HAProxy
configuration and LAPI passed in a separate loopback-only verification.
The guest was then powered off.

The resulting `easy-waf_1.6.1_offline_ubuntu24.04_amd64_private.iso` had

## Automatic CrowdSec bootstrap in the private ISO

Commit `546fbab` configures the original CrowdSec 1.8.2 DEB using its local
API debconf settings and the verified Hub index over loopback. With no
external network, the vendor CLI activated the Linux, HAProxy, SSH and
PostgreSQL collections. Two Ubuntu 24.04 container runs covered clean
configuration and retry after a simulated error disabling the Hub timer.
They also checked that a subsequent bootstrap kept existing local
configuration. The containers delegated service start to CrowdSec's
configuration test because systemd was outside their scope.

The first clean VMware run reached an active CrowdSec service and then
stopped at SPOA bouncer 0.4.0 configuration. A second reproduction on
Ubuntu showed that the vendor package's post-installation script copies
`examples/crowdsec.cfg` from its documentation directory. The file can
be excluded on minimal Ubuntu images. Commit `fcad2e7` tells dpkg to keep
that one file for the SPOA package transaction. The original bouncer DEB
configured successfully in the same loopback-only container. ShellCheck
and `make verify` passed.

The corrected private amd64 ISO was built from `fcad2e7`. After the upstream
CDN connection failed, the build used the independently verified packages
from the previous private ISO through a loopback repository. The package
manifests matched byte for byte. The dependency solve, installer
`--verify-only`, and the embedded snapshot's 101 checksums passed. The
corrected ISO SHA-256 was
`ed2320585f1d3e23eceee686222c68f66c7d77776935508241237d4a14eb0348`.

That ISO still stopped during the bouncer's post-install step on VMware.
Running the same post-install script without a terminal succeeded. A
separate loopback-only container test reproduced the script's silent
exit on a `vt220` pseudo-terminal, which supports a reset operation but
no color. Running it on the same terminal with its supported `NO_COLOR`
setting succeeded. Commit `0f445e3` passes that setting only during the
SPOA APT transaction.

A clean guest with a `vt220` console then configured the package and
reached service startup. The journal showed that the unprivileged SPOA
service could not read its YAML because the bootstrap inherited
`umask 077` and had created `/etc/crowdsec` with mode `0700`.
Commit `cb5f8c1` sets the package-compatible mode on newly created
directories. A Linux regression checked both the new mode and the mode
of a pre-existing directory. The original packages also configured
under `umask 077` in the loopback-only Ubuntu container, where the
packaged SPOA account could read its own configuration.

The private amd64 ISO from `cb5f8c1eb1514d2861561ced82f5232436f9c927`
had SHA-256 `e8209830c31cfc1502514004b3715cd3b3d6cf69482eda80457d850cd0a436b7`.
It passed the dependency solve, manifest checks, and independent Windows
hash verification. The ISO was mounted read-only on a fresh Ubuntu
24.04.5 VMware guest with no virtual NIC and no external IPv4 or IPv6
route. With `TERM=vt220` and `umask 077`, the shipped installer completed
using the local APT repository. The guest's APT source files kept their
original hashes, and the temporary Hub override was removed.

The packaged SPOA account could read its YAML. All ten checked units and
timers were active, including CrowdSec, SPOA, and the Easy WAF backup
timer. LAPI, the four CrowdSec collections, schema 028, all four
installed appliance executables, and trusted management HTTPS readiness
passed. The CrowdSec Hub refresh timer was disabled.

A second run from the same read-only ISO preserved the operator's local
CrowdSec override, main configuration, acquisition file, and Hub index
byte for byte. LAPI remained healthy. This verifies clean installation
and same-image reinstall for the private amd64 artifact. A different
package-version upgrade, arm64, and public distribution were outside this
test.

## ARM64 offline ISO

Source `9a7c2f9644488ed425f628ccb9bd83ebe53f74bc` built the ARM64 ISO
in the official Ubuntu 24.04.5 ARM64 container under Docker Desktop
emulation. APT verified the Ubuntu and pinned CrowdSec repositories and
resolved the closure against an empty package state. The isolated
repository contained 178 packages. The manifest contained only ARM64
and architecture-independent packages, including CrowdSec 1.8.2 and
SPOA 0.4.0. The release carrier held the CrowdSec packages and the Hub
snapshot remained on its own medium.

The extracted ISO passed `install.sh --verify-only`. The four packaged
ARM64 executables ran in the ARM64 container and reported version 1.6.1.
The Easy WAF DEB previously verified from `79d7f16` matched the ISO
payload byte for byte. Its SHA-256 was
`c5fd46aa2b0f9a0d04a4cdec9b1c1fba65c96af22853a6913983752cbe7ebe0b`.
The packaged source inputs were identical apart from an internal Go
test. The unsigned ARM64 ISO SHA-256 verified on Windows and Linux was
`2c4a27c6e4488b9111586c3b5a93cbbe936d6ff0672795da5a1df03e3f641d85`.

A full-system ARM64 QEMU run passed the missing-snapshot preflight and
reported startup of the CrowdSec, HAProxy, Fail2Ban and PostgreSQL units.
The fixture stopped the installation at its 15-minute deadline while the
guest disk was on the Windows bind mount. The deadline left full
installation unverified for that run.

The successful retry used a fresh Ubuntu 24.04.5 cloud image and QEMU
8.2.2 system emulation. Canonical's signature on the cloud image checksum
manifest and the image checksum both passed. The fixture moved its
working disk to Linux storage, raised the first-install deadline to 30
minutes, and temporarily masked the guest's scheduled APT jobs. The
appliance ISO and separate snapshot carrier were mounted read-only. The
guest had only loopback and no external IPv4 or IPv6 route.

The installer rejected a missing snapshot before creating configuration.
With the separately verified snapshot, it completed using the ISO's APT
repository and preserved the host's APT source files. Ten units and
timers were active. The four Hub collections, CrowdSec LAPI, schema 028,
trusted management HTTPS readiness, and byte-for-byte comparison of all
four installed executables passed. The temporary Hub override and
bootstrap state were removed, and the Hub refresh timer was disabled.

After unmounting the snapshot, a second run preserved the CrowdSec
configuration, local override, acquisition file and Hub index byte for
byte. LAPI remained healthy. The fixture reported success and shut down
normally. This covers ARM64 runtime in QEMU. Native hardware and release
signing remain separate acceptance checks.
