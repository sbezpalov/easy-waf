# Installed CrowdSec enforcement and recovery — e02aebb

On 2026-11-24, a fresh Ubuntu 24.04.5 amd64 VMware guest installed
[the exact e02aebb ISO](1.6.1-packages-e02aebb.md) without a network
adapter. Authenticated About reported 1.6.1 and
`e02aebbe36ea3ca52e3cb066e8a9f5f05883ab5a`. The installed CrowdSec
LAPI and SPOA bouncer were active. A temporary HTTPS publication used
an owned loopback backend and a local trust anchor.

| Check | Observed result |
| --- | --- |
| Baseline | Both loopback clients received trusted HTTPS 200 and the exact backend response. |
| Ban | A real three-minute LAPI decision caused HAProxy to return 403 to the selected client. The control client still received 200. |
| Unban | Deleting the decision restored the expected HTTPS 200 response. |
| Fail-open | With the same test client banned again and the bouncer confirmed stopped, HTTPS returned 200 while the decision remained active in LAPI. |
| Bouncer recovery | Restarting the bouncer restored 403 for the still-banned client. The control client still received 200. |
| Cleanup | The test decisions were absent, the watchdog was stopped, and both clients had the exact HTTPS 200 response with the bouncer active. |

A one-shot systemd timer was scheduled to restart the bouncer before the
outage test. The fixture removed the temporary publication and certificate,
revoked the session and powered off the guest.

This run covers enforcement and recovery on the installed candidate with
local clients. External mobile-network enforcement is recorded for an
[earlier PVE candidate](1.6.1-pve-ac05-mobile.md).
