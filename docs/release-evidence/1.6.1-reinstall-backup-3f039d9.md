# Candidate build, APT reinstall and packaged recovery on VMware

Test date: 2026-11-18, Europe/Moscow. The source commit was
`3f039d9216cc7006aedad0098963349aef490ce4` and the tree was
`30e9595a9e236999b56d887f3f406f71c4dfe4fd`.

## Artifact verification

The release workflow's preflight and build steps ran locally from that tree
using Go 1.27.4 on Ubuntu. The workflow and a separate Windows check agreed
on all four SHA-256 hashes.

| Unsigned artifact | SHA-256 |
| --- | --- |
| amd64 DEB | `9ed3973093b3d56439452ab91f20f334b16ca1e160d5a4fdd9d1a38f7b8d2b70` |
| arm64 DEB | `a87ba6df34d0fcdf984de8c1a06c0fcf8ae909205c5d48a0d14ecf7c1f9497be` |
| amd64 tarball | `f43de026fe3eef1e8f6029da984bddd7f6d0e2924504a125a03fef7b112f49be` |
| arm64 tarball | `da4a35c263209f80e4aaf6ea6c7172597c62d6e90dfc948bcc620f13e10a8236` |

The checks covered DEB version and architecture metadata, ELF architecture,
byte equality of the four binaries shared by each DEB and tarball, and
the amd64 version output for each packaged command. Both DEBs declare
`python3` and contain the source-matching libpq helper at mode 0644.
The packaged backup, restore and diagnostics entry points resolve to the
corresponding source-matching scripts.

## Installation and recovery

The isolated Ubuntu 24.04.5 amd64 VMware guest started with the
[4f64bc4 installation](1.6.1-pristine-vmware-4f64bc4.md). Its installed API
hash matched the previous candidate. The management API, HTTP test
publication and backup timer were already available.

APT rejected the first local-file invocation with `--no-download` before
replacing the package. Retrying with package sources disabled installed
the same-version DEB. The guest rechecked its SHA-256 before installation.
All four installed executables and all three running daemon executables
matched the verified package payload. The existing environment, management
certificate, HTTP publication and active backup timer were preserved.

The installed `easy-waf-backup` produced a mode-0600 archive containing a
readable PostgreSQL dump and the expected env file. The temporary libpq
service file was absent from the archive. After a fixture state file was
changed, the installed `easy-waf-restore` recovered its archived content
and the 28-record migration ledger. Console Apply succeeded with the
restored environment. The management certificate was byte-identical
and the backup timer was active after recovery.

An independent Windows client received the expected HTTP marker after
restore. Authenticated smoke from the tested source commit returned
20 passes, 0 failures and 2 skips for the legacy admin token and optional
MMDB. The guest was powered off with private test material on its disk.

## Release scope

The VMware execution covers a same-version amd64 reinstall and recovery.
The arm64 artifacts were inspected. The release notes generated during the
test selected only the `1.6.1` section of the changelog. At that point,
OpenClaw and the recent backup hardening were still under `Unreleased` and
were omitted. The subsequent [changelog reconciliation](../../CHANGELOG.md)
records those changes in the `1.6.1` section. A local replay of the release
preflight confirmed their inclusion and produced notes with SHA-256
`6665e9461ff79f57a3c6ddbe67b96b10551b3d1d1c17a095d392352740b01e29`.
Signed-release acceptance and browser-driven Apply are separate gates.
