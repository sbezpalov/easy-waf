# AC-05 on PVE with a mobile client

On 2026-11-18, the PVE development appliance served the existing HTTPS test
publication through HAProxy 2.8.30, CrowdSec 1.8.2 and the active CrowdSec SPOA
bouncer. The installed Easy WAF package reported version `1.6.1`. The observed
`easy-waf-api` executable SHA-256 was
`0d4b97d34fc53918b6975e287209a86b6b3cb3c0356c62c6503a4c9c0bfd19a1`.

The operator used a phone on mobile data with Wi-Fi disabled. A unique request
marker identified the test traffic in the HAProxy journal. The journal
correlated these HTTPS responses to the same public IPv4 client.

| UTC | HAProxy result | Observation |
|-----|----------------|-------------|
| 07:23:17 | 200 | The operator opened the publication without a certificate warning. |
| 07:24:43 | 403 | HAProxy identified the CrowdSec rule during the four-minute test ban. The operator saw 403. |
| 07:26:21 | 200 | After removal of the decision, the operator reopened the publication without a certificate warning. |

Only the temporary CrowdSec decision for the identified client was added and
removed. Cleanup was confirmed at 07:25:36 UTC and rechecked after recovery.
HAProxy, CrowdSec and the SPOA bouncer were active at the end of the run.
The report omits the mobile address and raw journal entries.

This run verifies external ban and recovery. Installed-bouncer fail-open and
restart were verified separately on the same dev appliance during the
[earlier CrowdSec acceptance](1.6.1-pve-c27-crowdsec-wan.md). The bouncer stayed
active throughout the mobile test.
