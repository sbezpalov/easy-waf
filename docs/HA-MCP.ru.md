# Безопасная публикация Home Assistant MCP

[English](HA-MCP.md) | **Русский**

Home Assistant умеет отдавать [MCP](https://modelcontextprotocol.io/) настольному
ассистенту. Это API, а не страница: клиент с доступом читает состояние и, в
зависимости от пользователя, меняет его. Easy Home WAF может опубликовать только
этот API, не открывая остальной Home Assistant.

Это политика на краю сети. Она не заменяет отдельного пользователя Home Assistant
с урезанными правами.

## Что делает профиль `ha-mcp`

Выберите профиль `ha-mcp` и не присылайте `path_policy`. API сохранит пресет
(`profiles.HAMCPPathPolicy`):

| Контроль | Значение |
|----------|----------|
| Allowlist | `/api/mcp`, `/mcp_server/sse`, `/auth`, `/.well-known/oauth-authorization-server` |
| Всё остальное | **404**. Блок-листы профиля и `restricted_paths` продолжают работать, в том числе на разрешённом пути |
| `/api/mcp` | заголовок `Authorization` должен начинаться с `Bearer `, иначе край отвечает **401**. 20 запросов / 10 с |
| `/mcp_server/sse` | таймаут простоя сервера 3600 с, 10 запросов / 10 с. Край здесь не проверяет `Authorization` |
| `/auth` | 40 запросов / 10 с, чтобы OAuth не упирался в более жёсткий лимит MCP |
| Лимит приложения | 40 запросов / 10 с (`rate_limit_burst` профиля) |
| `timeout server` бэкенда | 3600 с |

Префикс совпадает с самим путём и со всем, что под ним. `/api/mcp` пускает
`/api/mcp/assist` и не пускает `/api/mcp-other`.

`/.well-known/security.txt` по-прежнему закрыт. Документ обнаружения OAuth — другой
путь, он публикуется.

Если при обновлении не передать `path_policy`, сохранится уже записанная политика.
`"path_policy": {"mode": "default"}` оставляет таймауты `ha-mcp` без allowlist.
Тот же объект лежит в ответе `GET /api/v1/profiles` у записи `ha-mcp`.

## Таймаут клиента на HAProxy 2.8

В Ubuntu 24.04 стоит HAProxy 2.8. Действие `http-request set-timeout` меняет только
таймауты **server** и **tunnel**. Отдельного `timeout client` на один запрос нет.

Если какое-то приложение на фронтенде просит клиентский таймаут (пресет просит
3600 с для `/mcp_server/sse`), `timeout client` этого фронтенда становится
наибольшим из запрошенных, и ставится `timeout http-request 10s`, чтобы
незавершённый запрос всё ещё обрывался. Другие имена на том же порту делят этот
клиентский таймаут. Их собственный `timeout server` не меняется: молчащий бэкенд
по-прежнему останавливается на таймауте профиля.

Серверный таймаут на путь задаётся через `http-request set-timeout server` и
действует только на совпавший префикс. Побеждает самый длинный совпавший префикс.

## На стороне Home Assistant

Это делается на хосте Home Assistant. Easy Home WAF не сделает это за вас.

1. **Создайте пользователя без прав администратора** и только его отдавайте
   ассистенту. Токен владельца или админа может снять охрану и открыть замки.
2. Предпочтительнее **OAuth с PKCE**. Долгоживущий токен допустим, только если
   его можно отозвать и вы храните его как пароль. Передавайте его в
   `Authorization: Bearer`. Край проверяет, что заголовок есть и похож на bearer.
   Сам токен проверяет Home Assistant.
3. **Откройте этому пользователю небольшой набор сущностей** (или пайплайн Assist,
   на который смотрит `/api/mcp/assist`). Не открывайте замки, охрану и шторы,
   если вы этого не хотите.
4. В **`trusted_proxies`** укажите адрес, с которого Home Assistant видит этот
   appliance (LAN-адрес WAF или адрес моста Docker, если HA в контейнере на том
   же хосте). Иначе Home Assistant запишет все запросы как пришедшие от прокси,
   и его собственные лимиты и баны попадут не в тот адрес.
5. Если ассистент работает в облаке и подключается из другой страны, включите
   **GeoIP** для этого приложения и разрешите только нужные страны. Облачный
   клиент — это не ваш домашний IP. См. [GEOIP.md](GEOIP.md).

`/mcp_server/sse` в allowlist, потому что часть сборок Home Assistant стримит туда
после OAuth. Если ваша сборка требует bearer и на этом пути, добавьте правило с
`require_header: Authorization` и `require_value_prefix: "Bearer "`.

## Необязательный токен на краю

Правило пути может задать `edge_token_header` (например `X-Edge-Token`) и при
записи — `edge_token`. Токен лежит в файле под `<state>/secrets/edge-tokens/`,
режим `0640`: HAProxy (он в группе `easy-waf`) сравнивает заголовок, а в
сгенерированный конфиг значение не попадает. Его нет в PostgreSQL, его не
возвращает GET, и он не попадает в httplog HAProxy (журнал остаётся на строке
запроса; `capture request header` не используется). Край удаляет заголовок до
бэкенда.

Новый `edge_token` заменяет секрет, `clear_edge_token: true` удаляет его. Если
файл пропал, а правило считает токен настроенным, apply не проходит: отказ
закрытый.

Поле пароля в панели только на запись. Пустое поле при сохранении оставляет
текущий токен.

## Что проверить на настоящем Home Assistant

- Пользователь без прав администратора с токеном вызывает `/api/mcp` по
  опубликованному имени. Тот же вызов без `Authorization` даёт 401 на краю.
- Путь вне allowlist, включая веб-интерфейс Home Assistant, даёт 404.
- SSE или потоковая сессия переживает минуту тишины.
- В журнале Home Assistant при включённом `trusted_proxies` виден настоящий
  клиент.
- Отзыв токена в Home Assistant останавливает ассистента, хотя край проверял
  только форму заголовка.
